ElementBox — the atomic SysML v2 notation component

v0.1 · 2026-06-11 · Reference implementation for spec rules RG-1 (sizing/text), RG-9.2/9.3/9.5 (notation) · Companion to DEAL-Viewer-Layout-Rules-Spec.html

This is the component as it would ship in the viewer's render stage: framework-free JavaScript producing SVG, sized entirely by measured text (cached canvas.measureText, RG-1.2), integer coordinates (RG-1.6), definition/usage corner classification — «…def» square, usages rounded (RG-9.2) — arbitrary compartment count, arbitrary items per compartment. The <script> at the bottom of this file lifts directly into the viewer codebase as element-box.js.

Demo caveat: this page measures with the system font stack. Production loads the bundled woff2 via FontFace before Measure runs (spec D8) — same code path, pinned metrics.

4. Component contract

renderElementBox(spec, opts?) → { node: SVGGElement, layout: { width, height } }

spec = {
  keyword:       string            // rendered as «keyword», e.g. "part def", "part"
  ref?:          string            // RG-7.5: stable element identity (qualified name, e.g.
                                   // "VehiclePkg::Vehicle") — stamped as data-ref for go-to-definition.
                                   // Identity, never file/line: source spans are resolved at click time
  kind?:         'definition' | 'usage'
                                   // corner style: definitions square, usages rounded (RG-9.2).
                                   // Auto-classified when omitted: keyword ending in "def" → definition
  name:          string            // bold qualified name; may carry multiplicity, e.g. "cylinders[6]"
  compartments?: [                 // 0..N — count is open (RG-9.2)
    { title: string,               // italic centered category label
      items: (string |             // one per line, left-aligned, verbatim incl. +/−/# and [n..m] (RG-9.3)
        {text, ref?})[] }          // items are elements too — ref makes an entry navigable (RG-7.5)
  ]
  badges?: {                       // RG-9.8: status SLOTS, right-aligned in the keyword line.
                                   // Fixed order left→right; empty slots collapse (no reserve);
                                   // anything outside the registry is rejected, never drawn.
    semantic?:     'abstract' | 'variation' | 'redefinition'  // slot 1 (innermost) — dim letter glyph
    diagnostics?:  { errors?: n, warnings?: n }               // slot 2 — worst severity wins, count caps at 9+
    verification?: 'pass' | 'fail' | 'unverified'             // slot 3 (rightmost, the corner) — ✓ / ✗ / ○
  }
  collapsed?:    boolean           // RG-9.7: fold to header + footer; ignored without compartments
}
opts = { maxWidth?,
         onToggle?:   (collapsed) => void,  // fold-footer click callback (RG-9.7)
         onNavigate?: (ref) => void,        // RG-7.5: Cmd/Ctrl+click or dblclick on any data-ref carrier.
                                            // Component emits identity only; the shell resolves ref →
                                            // source span (model index / LSP) and opens the editor.
                                            // Production uses one delegated canvas listener instead.
         theme via CSS vars --eb-* }
Token Value Rule
fonts: keyword 11 / name 13 bold / title 10.5 italic / item 12 see EB_TOKENS.fonts RG-1.3, RG-9.2
min box 80×40 · max width 240 · name ≤3 lines · truncation ≥8 chars + tooltip minWidth/minHeight/maxWidth/nameMaxLines/minTruncChars RG-1.1, RG-1.4
header rule = box stroke weight (1.5px) · compartment rules 1px · 1.5px box stroke rules, stroke RG-9.2
corners: definitions («part def», «requirement def», …) square 0px · usages («part», …) rounded 8px, auto-classified by keyword suffix def, overridable via kind cornerRadius RG-9.2
fold footer: 16px full-width strip + centered chevron (10×5). Header-only elements get neither header rule nor footer (the box closes them); ANY compartment content gets both. Present in both fold states; collapsed reuses the header rule as its separator (no double line); whole strip is the click target; chevron up = fold, down = expand footer RG-9.7
badge slots: 3 named slots (semantic | diagnostics | verification), fixed order, verification outermost at the corner; content restricted to badgeRegistry + computed diagnostics; tones limited to good/warn/bad/dim; per-glyph measured widths; mandatory tooltips; invalid content rejected and reported via layout.badgeInvalid badge, badgeRegistry, resolveBadges() RG-9.8
padding x 12 · badge reserve measured per occupied slot in keyword line pad, badge RG-2.5 (box-local), RG-1.5/RG-9.5
all coordinates integer; measurement cached per (font, string) createMeasurer RG-1.2, RG-1.6, RG-8.1
theming: paint-only via CSS vars (--eb-accent/-header-fill/-outline/-rule/-kw/-sep) keyed off data-family/data-kind; brand palette by family with dark-mode variants; separators inset 12px in all themes (geometry constant); standard black = omit .eb-brand eb-theme.css (in this file's <style>) RG-9.6

Theme contract: switching themes never re-runs layout — the playground toggle swaps a CSS class on the container while the SVG stays untouched. Text contrast in both palettes targets WCAG 4.5:1; names stay near-black/near-white because they carry the information, color carries only the family.
